# Linux/Unix 기술적 점검 항목 표준 목록

> 이 문서는 ISMS-P 인증 준비에 활용하기 위한 기술적 점검 항목의 표준 목록이다.
> 아직 점검 코드는 작성하지 않는다. 원본 문서에서 추출한 사실과 해석을 구분한다.

## 읽는 방법

- **KISA 항목**: `docs/sources/kisa/기술적_취약점_분석평가_방법_상세가이드_2026.pdf` "01. Unix 서버" 장의 U-01~U-67.
  - 각 항목은 가이드에 **PASS(양호)/FAIL(취약) 판단 기준이 모두 명시**되어 있다.
- **ISMS-P 인증기준**: `docs/sources/isms-p/ISMS-P_인증기준_안내서_2023-11-23.pdf` 제2장의 인증기준 번호.
  - 아래 ISMS-P 매핑은 원본 문서에 명시된 1:1 매핑이 아니라 **해석**이다.
- **ISMS-P 세부점검항목**: `docs/sources/isms-p/ISMS-P_인증기준_세부점검항목_2023-10-31.xlsx`의 항목번호.
  - 세부점검항목의 항목번호는 인증기준 번호와 동일하다(예: 2.5.4). 해당 행의 "주요 확인사항"이 대응한다.
- **자동화**: AUTO(명령/설정값으로 자동 판단) / SEMI(기술 자동화 가능하나 사람 확인 필요) / MANUAL.
- **출처**: KISA 상세가이드 01. Unix 서버 (분야별 페이지), ISMS-P 안내서 제2장.

## 매핑 요약 및 향후 필요사항

### ISMS-P와 직접 매핑 가능한 항목 (해석)

- KISA 67개 항목 전부가 ISMS-P 인증기준과 개념적으로 연결 가능하다(상세가이드의 "서버 OS 보안 설정 취약점" 점검 방법론으로서).
- 다만 원본 문서 간 명시적 1:1 매핑은 없으므로, 모든 매핑은 해석이다.

### 매핑이 불명확하거나 추가 정책·문서가 필요한 항목

아래 항목은 조직 정책/기준값에 따라 판단이 달라져, 자동화 시에도 기준값 입력이나 사람 확인이 필요하다.

| ID | 사유 |
| --- | --- |
| U-07, U-08, U-09 | "불필요한" 계정/그룹 판단에 조직 기준 필요 |
| U-23, U-25, U-33 | 불필요 SUID/SGID·world writable·숨김 파일의 "불필요" 판단 필요 |
| U-26 | /dev 존재하지 않는 device 파일 제거 판단 필요 |
| U-45, U-49 | 메일/DNS(BIND) 취약 버전 판단에 취약점 DB·버전 기준 필요 |

| U-66 | 로그 기록 정책(보안 정책) 필요 |

### ISMS-P 매핑 시 유의 (프로젝트 원칙)

- KISA U-xx의 양호/취약 판정은 **기술적 취약점 점검 결과**이며, ISMS-P 인증기준 충족을 의미하지 않는다.
- ISMS-P 인증기준(예: 2.5.5 특수 계정·권한 관리)은 기술 설정 외에 신청·승인·목록·검토 등 **관리적 증거**를 요구한다.
- 따라서 표의 "ISMS-P(해석)" 컬럼은 기술 점검과의 관련성을 나타낼 뿐, 해당 기술 점검의 PASS가 곧 ISMS-P 충족이 아니다.
