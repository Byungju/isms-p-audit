## 1. ISMS-P 인증기준 안내서

| 항목 | 내용 |
| --- | --- |
| 문서명 | 정보보호 및 개인정보보호 관리체계(ISMS-P) 인증기준 안내서 |
| 버전/발행일 | 2023. 11. (안내서 발간시점 기준 2023년 10월) |
| 발행처 | KISA(한국인터넷진흥원) |
| 파일 | `docs/sources/isms-p/ISMS-P_인증기준_안내서_2023-11-23.pdf` |
| 분량 | 262쪽 (PDF) |

### 목적

정보통신망법 제47조(정보보호 관리체계의 인증), 개인정보 보호법 제32조의2(개인정보 보호 인증), 그리고
"정보보호 및 개인정보보호 관리체계 인증 등에 관한 고시"(과기정통부고시 제2023-33호, 개인정보보호위원회고시 제2023-8호)에서
규정한 사항을 구체적으로 설명하기 위한 문서.

### 전체 구성

- 제1장: 인증기준 개요
  - 인증기준은 3개 영역(1. 관리체계 수립 및 운영 / 2. 보호대책 요구사항 / 3. 개인정보 처리 단계별 요구사항), 총 **101개** 인증기준으로 구성.
  - ISMS 인증 신청기관은 영역 1·2의 **80개**, ISMS-P 인증 신청기관은 영역 3을 포함한 **101개** 적용.
  - 영역별 분야 수: 1. 관리체계 4개 분야 16개, 2. 보호대책 12개 분야 64개, 3. 개인정보 5개 분야 21개.
- 제2장: 인증기준 설명 (본문, 각 인증기준을 항목별로 상세 설명)

### 각 인증기준 항목의 세부 구성 (제2장)

각 항목(예: 2.9.1 변경관리)은 다음 순서로 기술되어 있다.

1. **항목** (항목 번호·명칭, 예: 2.9.1 변경관리)
2. **인증기준** (요구사항 문장)
3. **주요 확인사항** (점검 질문 형태, 복수 항목)
4. **관련 법규** (해당 항목에 한함)
5. **세부 설명** (요구사항 해설, 예시, 포함사항)
6. **증거자료 예시** (예: 변경관리 절차, 변경관리 수행 내역 등)
7. **결함사례** (예: 사례 1, 2, 3 …)

### 주요 내용

- 관리체계 수립·운영, 보호대책, 개인정보 처리 단계별 요구사항의 **관리적·기술적 요구사항**을 인증기준 단위로 기술.
- "주요 확인사항"은 심사 시 확인할 질문, "증거자료 예시"는 제출/확인할 증적의 예, "결함사례"는 미흡 사례를 제시.

### 프로젝트에서의 활용 목적

- ISMS-P 요구사항의 원본 기준(인증기준 문구) 확인.
- 각 인증기준별 "주요 확인사항", "증거자료 예시", "결함사례"의 원문 출처.
- 기술적 점검 자동화 항목과 ISMS-P 인증기준 간 매핑의 근거 문서.

## 2. ISMS-P 인증기준 세부점검항목 (본인증)

| 발행처 | KISA |

### 목적

ISMS-P 인증기준을 **세부 점검항목(체크리스트) 수준으로 세분화**한 문서. 각 인증기준을 "상세내용"과 "주요 확인사항"으로 나눠 제시한다.

### 전체 구성

3개 시트로 구성되며, 시트명은 인증기준의 3개 영역과 동일하다.

| 시트 | 인증기준 수 | 세부항목 수 |
| --- | --- | --- |
| 1. 관리체계 수립 및 운영 | 16개 | 42개 |
| 2. 보호대책 요구사항 | 64개 | 195개 |
| 3. 개인정보 처리단계별 요구사항 | 21개 | 91개 |
| **합계** | **101개** | **328개** |

### 시트 내 컬럼 구성

각 시트는 다음 컬럼으로 구성되어 있다 (열 기준).

| 컬럼 | 내용 | 예시 |
| --- | --- | --- |
| 분야 | 영역 내 분야 번호 | 2.1. / 2.9. |
| 항목(분야명) | 분야 명칭 | 정책, 조직, 자산 관리 |
| 항목 번호 | 인증기준 번호 | 2.1.1 |
| 항목명 | 인증기준 명칭 | 정책의 유지관리 |
| 상세내용 | 요구사항 문장 | (인증기준과 동일 계열의 기술) |
| 주요 확인사항 | 점검 질문 (복수 행) | (확인 질문) |

> 참고: 하나의 항목번호/항목명에 대해 "주요 확인사항"이 여러 행에 걸쳐 기재된다(병합 구조).

### 주요 내용

- 본인증(ISMS-P 전체) 대상 세부점검항목.
- 안내서의 "인증기준 + 주요 확인사항"을 표 형태로 재구성한 것. **결함사례·증거자료 예시는 포함하지 않음.**

### 프로젝트에서의 활용 목적

- 세부 점검항목(확인사항)의 기계적 파싱/구조화를 위한 원천 데이터.
- 향후 점검 항목 ID 부여 및 자동화 매핑의 기초.

## 5. 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드

### 목적

| XII | 클라우드 | 계정 / 권한 / 가상리소스 / 운영 |

### 각 점검항목의 세부 구성

각 점검항목(예: U-01 root 계정 원격 접속 제한)은 다음 순서로 기술된다.

1. **항목코드 / 중요도(상·중·하) / 점검항목명 / 분류 경로** (예: `U-01`, `(상)`, "root 계정 원격 접속 제한", `UNIX > 1. 계정 관리`)
2. **개요**: 점검 내용 / 점검 목적 / 보안 위협 / 참고(용어 정의)
3. **점검 대상 및 판단 기준**: 대상(OS 목록) / 판단 기준(양호·취약) / 조치 방법 / 조치 시 영향
4. **점검 및 조치 사례**: OS별(SOLARIS, LINUX, AIX, HP-UX 등) 설정 파일·명령어 수준의 점검/조치 예시

### 주요 내용

- 점검 항목별로 **점검 명령어·설정 파일·판단 기준(양호/취약)**이 구체적으로 제시되어 기술적 점검 자동화에 직접 활용 가능.

### 프로젝트에서의 활용 목적

- Linux/Unix 서버 기술적 점검 항목(U-01~U-67)의 점검 방법·판단 기준 원천.
- 향후 자동화 점검 스크립트의 "점검 방법 / 양호·취약 조건 / 조치 방법" 참조.
